## 3. Small unverified details

| # | Detail | Status |
| --- | --- | --- |
| 3.2 | Odd blend modes being additive | Code: the frame buffer is RGB565 (`sceGuDrawBuffer`, GE 0xD2), so there is no destination alpha and nothing can write it; stencil is never enabled. The GPU then reads destination alpha as 0, so `ONE_MINUS_DST_ALPHA` = 1 (standard PSP behaviour, as emulated by PPSSPP). Needs a screenshot to confirm. |
| 3.8 | Depth between effects and combatants | Resolved from code: camera-0 sprites get GE z = 65535/viewDepth (~85–400), duel units and HUD 0x7FFF−depth, test GEQUAL, so 3D effects should be hidden behind the opaque pixels of the units and the HUD. The player emulates this (toggle "depth test"). Needs a screenshot of a duel effect. |
| 3.10 | Prim2D "lines" drawn as triangle strips | Code: `prim2DDraw` always sends a 4-vertex triangle strip and `prim2DInit` zeroes the corners but not the colours, so the outlines of window styles 2, 6 and 8 become shaded fans from the window origin ([windows.md](windows.md#prim2d-and-the-line-quirk)). Only unused styles are affected. Needs a screenshot (e.g. a text patched with ＠ｔ０６). |
| 3.11 | Map board against a real screen | Code: the board, background billboard, scenery and tokens are drawn through `g_mapCamera` with the exact projection ([map-board.md](map-board.md)); in the viewer the squares sit on the painted floors of the boards checked (stages 1, 2, 9, 11, 15). Needs an emulator screenshot of a board (and the GE texture filter setting, which was not checked). |

## 4. Known dead ends (written but never read, or never used)

These are closed: there is nothing left to recover.

- **ScrCamera +0xD8..+0xF0** (`cam_config`, `cam_viewport`): written but never read by any code.
- **Negative archive indices** in `scr_LoadSprite/scr_LoadAnm`: they read a container table that is never filled.
- **GAN**: the step x/y bytes, header byte +0x0A and the trailing list are all skipped or unread.
- **`snd/bgm.dat`**: the VAG copy of the music is never opened. The music comes from `at3/*.at3`.
- **Font glyphs 756–848 and 7560–7949**: they have ink but no Shift-JIS code maps to them.
- **goc.dat prefix 100** (177 clips): no text references them.
- **Script cameras 1–5 and 7**: set up at boot but never drawn; only cameras 0 and 6 have a render pass. The battle-field camera 3 is therefore never seen through by effects.
- **CardDef +3C/+3D**: no code reads them (only struct copies); closed ([card-effects.md](card-effects.md)).
- **Save fields written but never used**: profile +0x18 in story mode, deck +0x58/+0x5C, header +0x60/+0x6C; the play-time counter is never advanced.
- **Stage 16** (Hellgaia rematch) is not reachable from the stage table; the `EXPORT.BIN` / ULJM05365 save path is never called.
- **Never-loaded archive data**: card.one 10020 and the character GANs 1001–1021, unit.one `/10` `/11` (copies of card.one 10010/10020) and `/24`, chara.one 1000/101–411 (face copies), etc.one 330/340 and most 310 plates, map.one decorations 301+ ([database.md](database.md)). The 3 GBP files with short fill-run data are among them; the game would read the next bytes of the entry.
- **Duel attack-effect override** (0x088F6224): zeroed at duel init before any read; the unused RPG-engine block (items, party, date) behind script functions 0x10F–0x12E is never filled.
- **Scene 400** is an unreachable stand-alone "How to play" viewer (`rulesHelpScene`, which is also the map board's Help command: [extras.md](extras.md)); scene 4000 is the ad-hoc lobby.
- **Window +0x04 and +0x8E** (shorts in struct `Window`): never accessed by any decompiled code; padding.
- **Debug and test scenes** (9000, 0x186, 0x5DC, 2000): unreachable, and the `one/…` loose files they
  read are not on the UMD.
